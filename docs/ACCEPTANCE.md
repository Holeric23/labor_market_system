# Итоговая приёмка — этап 12

Дата: **13.10.2026**, Asia/Yekaterinburg. Объём: существующая реализация этапов 0–11, без добавления продуктовых функций и косметической переработки. Исходный `docs/system_plan.md` сохранён. Нумерация 0–12 — детализация его укрупнённых этапов 0–5, а не новое ТЗ.

**Обязательный автономный сценарий 1–12 пройден.** Это приёмка локальной реализации на Windows с явно имитируемыми источником и транспортом Telegram. Живые интеграции и Linux не приняты. Качество модели и готовность публичного сервиса этим результатом не утверждаются.

Контрольная установка создаётся `scripts/check_stage12.py` обычными копиями под `.artifacts/stage12-control-*`. Она содержит собственные SQLite, исходники, настоящий локальный Ensemble и словари. Один реальный текст читается только из **новой** `data/app.db`, дополнен контрольными требованиями; старый проект для исполнения не читается. Audit hook запрещает доступ к старому дереву и внешние socket connect/bind; внутренние loopback-сокеты Windows asyncio допустимы. Источник выдаёт контрольные `RawPublication` через штатный Collector; доставка сохраняет настоящие события/попытки/квитанции через worker с имитируемым sender. ## Найденные дефекты и исправления

1. `scripts/check_stage0.py` ошибочно считал константу запрета старого пути и отрицательный тест исполняемой зависимостью, а штатный `verify.ps1` требовал наличия старого дерева и исторической инвентаризации. Обычная структурная проверка теперь автономна, проверяет AST/несвязанные файлы; строгая прежняя сверка сохранена как явный `--verify-originals`. Независимость исполнения дополнительно доказывается запретом I/O в полном сценарии, а сохранность — отдельным полным SHA-256 before/after, без изменения прежних manifests.
2. README и таблица состояний отстали от реализации: этапы 10–11 были помечены не начатыми, подключение Telegram — будущим. Исправлены фактические статусы, текущие команды и ограничения. Исторические результаты этапов не переписаны.
3. Первый новый проверочный сценарий запретил внутренний loopback asyncio и остановился до сценария. Исправлен только ограничитель проверки, повторный и окончательный прогон прошли; никаких пустых продуктовых заглушек не добавлено. Первый sandbox pytest с WinError 5 сохранён в `stage12-tests.log`; разрешённый повтор и документированная команда прошли. Auto-review не отклоняла запрошенные автономные запуски.

Прикладные алгоритмы ML/извлечения, схема и продуктовые функции не изменены: полный сценарий и регрессия не выявили требующих исправления дефектов в них.

## Не проверенные живые интеграции и платформы

- **Telegram Bot API:** действительный BOT_TOKEN/ADMIN_USER_IDS, получение обновлений aiogram, реальные sendMessage, права пользователей, rate limits и реальные квитанции. Проверен только controller и имитируемый транспорт. Требуются собственный токен BotFather, OWNER ID, private env/ACL, `/allow ID`, явное включение polling/delivery.
- **Telegram/Telethon-сбор:** API ID/hash, отдельная новая session, телефон/код/2FA, доступ к выбранным каналам, реальная сеть. Токены/сессии не переносились и login не выполнялся.
- **DesignHunters:** живой сайт, селекторы, установленные Chromium/Playwright и системные библиотеки, действительные URL CSV. Проверены автономные parser/adapter-контракты, а не нынешний внешний сайт.
- **Linux:** чистая установка/closure lock, glibc, реальные systemd units, группы процессов на Linux, загрузка после reboot, Playwright и восстановление на целевом хосте. Linux wheel availability этапа 11 не заменяет эти проверки.
- **Публичный сервер:** домен/DNS, реальные TLS-сертификаты, nginx, firewall, внешний доступ друзей, резервирование на другом носителе и reboot. Сервер не опубликован; настройки владелец выполняет отдельно.
- **Эксплуатационная нагрузка:** конкурентные читатели/писатели, холодный кеш, длительная работа, физическое повреждение/потеря питания, массовый новый ML-прогон. Нет утверждения об их прохождении.

Все проверочные процессы завершены. Автономная приёмка закончена; работа остановлена после этапа 12. Настоящие интеграции и сервер требуют отдельной настройки и проверки.
