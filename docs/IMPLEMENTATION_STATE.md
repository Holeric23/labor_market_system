### Реализация

- Классы, связи, evidence, каталог, публикации, статус документа, прогресс и checkpoint коммитятся одной транзакцией пакета. Исключение откатывает весь пакет. Повтор продолжается с checkpoint; полная замена проекции выбранного документа удаляет прежние связи, включая снятые навыки. no_classes — явный статус, не отсутствие обработки.

Проверка ready включает точное совпадение ID с job_inputs, полноту трёх таблиц, статусы, FK, публикации и прогресс. Активный указатель автоматически не переключается.
- Подтверждённые revisions импортированной разметки читаются mode=ro. Последняя подтверждённая ревизия выбранного dataset имеет приоритет над ML; более поздний draft её не отменяет. Источник разметки не изменяется. Evidence сохраняет machine, effective и confirmed_correction. Это поддержка сохранности исправлений, не новый интерфейс редактирования. Ревизия фиксирована на момент submit; новые исправления требуют нового задания.

У одного источника не более одного queued/running-сбора, включая конкуренцию history/new и расписания. После аварии running возвращается в queued; повтор сохраняет курсор и увеличивает attempts. Если после ошибки источник уже продвинут другим заданием или перенастроен, старый retry запрещён: требуется новый запуск.
- TelegramParser получил managed_batches поверх существующего Telethon-клиента и построения URL. history идёт назад от зафиксированной верхней границы, сохраняет history_offset/high_water и признак исчерпания истории. max_items ограничивает одну порцию истории; следующий history продолжает её. new требует хотя бы одной порции history, проверяет ограниченное перекрытие последних overlap_days/overlap_limit сообщений и новые ID по возрастанию до фиксированной upper_id. Пустые сообщения не превращаются в Content, но продвигают подтверждённый курсор.
- DesignHuntersParser использует прежний _parse_page и selectors. Добавлен режим фиксированного списка URL, пакетного прохода и продолжения. Список читается из локального CSV при enqueue и сохраняется в config_json. history продолжает history_index, new циклически проходит список через regular_index. Изменение списка сбрасывает индекс нового задания. Автоматического поиска URL сайта нет, upstream-курсора у этого парсера нет. Ошибка страницы поднимается в задание, а не выдаётся за успешное завершение списка.
- Пакет одной транзакцией сохраняет Content, Publication/новую ревизию, курсор задания и источника, счётчики, а также durable-запись передачи в обработку. Сбой до commit откатывает всё; после commit повтор начинает со следующей позиции. Предшествующие пакеты сохраняются при ошибке источника. Ошибка закрытия соединения после последнего commit отображается как Cleanup; завершённые данные не откатываются и другие источники продолжают работу.
- Точный повтор текста использует прежний Content. Совместимость legacy text_hash учитывается только при полном равенстве исходного текста; whitespace-правка получает отдельное содержимое, чтобы не терять текстовую ревизию. Повтор URL/того же текста не добавляет новую ревизию. Новый URL того же текста создаёт только Publication. Возврат к прежнему тексту создаёт новую ревизию связи с уже существующим Content.
- Первичная строка publications не переписывается. publication_revisions хранит историю связей с Content, дату публикации, время наблюдения, внешний ID и задание сбора. При первой правке legacy-публикации сохраняется исходная ревизия с неизвестным observed_at=NULL. current_publications показывает последнюю связь. Старые result_publications остаются неизменными; validate допускает сохранённую историческую связь. Новые задания обработки фиксируют текущие связи, в том числе при копировании неизменённой части каталога. Исходные исторические Content и их карточки сохраняются, даже если в новом наборе у них больше нет текущих публикаций.
- collection_handoffs создаётся при изменении публикаций, включая новый URL уже известного текста. Worker объединяет ожидающие пакеты в incremental-задание. Создание processing job и запись его ID в handoff атомарны. Если активная модель/набор несовместимы или настройка обработки отсутствует, данные остаются сохранёнными, ошибка передачи видна OWNER, повтор отложен на 60 секунд или запускается кнопкой. Полная ML-пересборка автоматически не запускается, active_result_set не переключается.
- Расписание хранится в SQLite и работает в том же worker. По умолчанию выключено; интервал 60..31536000 секунд. После перезапуска просроченный запуск ставится один раз, пропущенные интервалы не воспроизводятся пачкой. Уникальный индекс и BEGIN IMMEDIATE исключают наложение по источнику. Для Telegram перед включением регулярного расписания следует явно начать загрузку истории.
- OWNER: /sources, создание/настройка источников, history/new, состояния, ошибки, прогресс пакетов, retry, ссылки на processing jobs и повтор передачи. USER запрещены GET и все POST. CSRF обязателен. Отключение источника останавливает его queued/running-задание до следующего сохранения пакета; изменение параметров активного задания запрещено. Адрес, тип и имя уже зарегистрированного источника неизменяемы; для иной идентичности создаётся новый источник.
- Отдельный CLI `collection setup-telegram` сохраняет API ID/hash со скрытым вводом в `state/collection/telegram.json`; `login-telegram` создаёт/авторизует только `state/collection/telegram.session`, запрашивая телефон, код и 2FA скрыто. Worker не читает старую .env, не импортирует старую сессию и не выполняет интерактивный вход. При отсутствии локальной авторизованной сессии задание получает ошибку.
