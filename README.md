# Система поиска вакансий

Практическая система с Telegram-ботом, административным Telegram Mini App, PostgreSQL и отдельно запускаемыми парсерами. Это новая независимая реализация; старая SQLite-база и её файлы не изменяются. При создании базы регистрируются 17 Telegram-каналов из предыдущего проекта; публикации в новую базу не переносятся, массовый сбор автоматически не запускается.

## Состав

- bot/ — бот; bot/miniapp/ — административная панель внутри приложения бота.
- database/ — схема PostgreSQL, миграция, операции доступа и поиск.
- parsers/ — существующие Telegram- и DesignHunters-адаптеры, обработка моделью и короткий запуск парсеров.
- parsers/models/ — независимые копии рабочих файлов модели и словарей. Этот каталог не включается в Git и Docker-образы; его нужно сохранять отдельно.
- database/collection.py — общий менеджер очереди, расписания и срока хранения; scripts/parser-scheduler.ps1 может дополнительно поставить просроченные задания в очередь.
- tests/ — автономные тесты; .artifacts/ — их временные данные.

## Подготовка

Нужны Docker Desktop и Compose. Создайте собственный файл .env на основе .env.example и задайте отдельный пароль PostgreSQL, URL подключения через имя database, токен бота, ID владельца и HTTPS-адрес Mini App. URL должен содержать URL-кодированные специальные символы пароля. Храните секреты и Telegram-сессии только в локальных файлах, исключённых из Git.

В compose.yaml закреплено имя проекта labor-market-system и три роли: database, bot и parser. База хранится в data/postgres; бот и панель работают в контейнере bot. Контейнер parser ожидает задания в общей очереди и запускает сбор только по команде из панели или при наступлении включённого расписания. При запуске bot контейнер parser запускается вместе с ним. Дополнительный скрипт scripts/parser-scheduler.ps1 обращается к тому же менеджеру и не обязателен для работы встроенного планировщика. Пустые или отключённые источники и выключенное расписание не вызывают внешний сбор. В панели доступны запуск по одному или всем источникам, состояние и отмена заданий. Для Telegram сначала нужен первичный сбор истории. Одновременно работает один исполнитель.

Для парсера Telegram нужны TELEGRAM_API_ID, TELEGRAM_API_HASH и сессия пользовательского аккаунта. Владелец может создать сессию в Mini App: «Источники» → «Аккаунт Telegram для парсера». Парсер должен быть запущен; номер, код и пароль передаются только для входа и не сохраняются в настройках или PostgreSQL. Сессия сохраняется в state/collection. Для DesignHunters браузер включён в образ парсера; источник соответствует одной настроенной странице, автоматического обнаружения новых URL нет.

Телеграм-каналы хранятся в отдельной таблице telegram_sources, связанной с общим реестром sources: общие настройки, история запусков и публикации остаются у одной записи источника. Первые 17 адресов восстановлены по ссылкам публикаций предыдущего проекта; количество старых публикаций сохранено только как сведения о происхождении и не означает, что эти публикации перенесены. Адреса не проверялись в действующем Telegram, поэтому их текущая доступность и актуальность ещё требуют проверки. Источники включены для ручного запуска, расписание у всех выключено. Повторное применение миграций не меняет пользовательские настройки; написание имени канала без учёта регистра не создаёт дубликат.

В разделе «Источники» задаётся актуальность публикаций в днях, считая от даты публикации. Telegram-сбор проходит от новых сообщений к старым и прекращается на границе актуальности; это работает и при выключенной очистке. Если достигнут максимум публикаций за запуск, следующий запуск продолжит сбор с сохранённого места. Автоматическая очистка по умолчанию выключена; её можно включить после успешного сбора. Неизвестная дата не является основанием для удаления. Сохранённые пользователями вакансии и записи с ручными исправлениями сохраняются; устаревшие сохранённые публикации исключаются из общего поиска, но доступны владельцу через сохранённое. Удаляемые записи исчезают также из исторических наборов результатов. Пробные счётчики клиентов не обнуляются.

В административном разделе «Источники» можно добавлять источники, менять название, адрес, параметры и расписание, а также удалять и восстанавливать записи. Удалённый источник выключается, а публикации и история запусков остаются в базе. Восстановленный источник остаётся выключенным до явного включения. При изменении адреса создаётся новая запись, а прежняя переносится в удалённые, чтобы история не перешла к другому каналу. После удаления или изменения настроек выполняющийся сбор не сможет сохранить следующий пакет со старыми настройками.

Запуск docker compose up -d database bot создаёт или обновляет PostgreSQL-схему и при настроенном токене подключает бота к Telegram. Доступ клиентов по умолчанию выключен и управляется в админ-панели без перезапуска; в выключенном состоянии бот сообщает клиентам о недоступности, а владельцы открывают панель командой /admin. Локальный порт панели доступен только на 127.0.0.1; вход Mini App требует реального HTTPS с корректно настроенным обратным прокси, допустимым Host и явно доверенным IP прокси. До настройки HTTPS и реального токена доступ администратора не подтверждён.

## Развёртывание на сервере с HTTPS

Установите Docker и Compose на сервере, скопируйте проект вместе с рабочими файлами `parsers/models/` и создайте `.env`. Заполните секреты и `ADMIN_DOMAIN` доменным именем панели без `https://` и пути. DNS-запись домена должна указывать на публичный IP сервера; отдельно записывать этот IP в `.env` не требуется. Если своего домена пока нет, можно подобрать бесплатное DNS-имя с помощью sslip.io, учитывая, что это домен стороннего DNS-провайдера, а не собственный зарегистрированный домен.

Убедитесь, что внешние порты 80 и 443 направлены на сервер и свободны. Запустите `docker compose -f compose.yaml -f compose.server.yaml up -d`. Контейнер HTTPS автоматически получает и обновляет сертификат; он передаёт запросы панели напрямую контейнеру бота. `ADMIN_MINIAPP_URL`, разрешённый хост и адрес для входа парсера формируются автоматически. На локальном компьютере обычный `compose.yaml` не публикует панель наружу. Серверную конфигурацию и выдачу сертификата нужно проверить на реальном сервере.

## Границы текущей реализации

В панели доступны клиенты и периоды доступа, источники, права менеджеров, размер подборки (по умолчанию 5), текст стоимости, управление заданиями сбора и срок хранения публикаций. В разделе «Бот и документы» владелец добавляет постоянную HTTPS-ссылку, версию и полный утверждённый текст каждого документа. Условия, политика и согласие обязательны до начала настройки поиска: пока они не опубликованы, бот не предлагает фиктивное согласие и поиск закрыт. Менеджера для связи настраивают в разделе «Настройки».

В Telegram предусмотрены пошаговая настройка поиска, несколько сохранённых фильтров, подборки по запросу, карточки и сохранение или скрытие вакансий. Предусмотрены три успешные бесплатные подборки, затем поиск требует действующего периода доступа или ручного разрешения администратора. Поиск сейчас поддерживает специальность и навыки из имеющихся справочников, формат и зарплату; опыт, география и произвольные исключения пока не реализованы. Автоматическая рассылка вакансий выключена. Первичная наполняемость новой базы зависит от отдельно настроенных и явно запущенных источников. Для обычного режима Telegram сначала требуется явно выполненный исторический сбор конкретного канала; автоматически история не собирается. Существующая SQLite-база остаётся в старом проекте и не импортирована.

Выдача доступа через inline-режим требует включить его у BotFather и добавить Telegram ID менеджера в панели. Менеджер в чате вводит @имя_бота, при необходимости через пробел — количество дней, и выбирает карточку; клиент активирует доступ в боте после подтверждения опубликованных документов. Подготовленная ссылка действует 24 часа и может быть погашена только один раз. Её можно переслать: доступ получит первый активировавший. После проверки администратором реальной оплаты действующий период продлевается от текущего окончания. Этот сценарий не заменяет проверку правил Telegram и условий оплаты и пока не проверялся с настоящими аккаунтами.

Проверки с синтетическими данными и настоящей моделью не подтверждают работу реального Telegram Bot API, авторизацию сборщика, реальные источники, HTTPS-прокси, боевые данные, производительность или восстановление боевой базы. Не запускайте два экземпляра бота с одним токеном; parser использует блокировку одного исполнителя в PostgreSQL.
