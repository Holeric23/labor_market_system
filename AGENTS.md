# Обязательные правила

- Старый проект `C:\Study\Анализ данных\Итоговый проект\Python_research_project` разрешено только читать. Запуск его скриптов, создающих файлы, запрещён.
- Все записи, тестовые БД, временные файлы и артефакты находятся внутри `C:\Study\MatchArt\labor_market_system`. Перед тестами направлять TEMP, TMP, TMPDIR и кеши в `.artifacts` этого проекта.
- Не использовать старую БД, окружение или модели как изменяемую рабочую зависимость. Не создавать ссылки на них. БД и модели переносить только на отдельно запрошенном этапе.
- Архитектура: модульное Python-приложение, SQLite, FastAPI/Jinja2, aiogram; один исполнитель заданий. Без микросервисов, Redis, Elasticsearch и отдельного SPA.
- Исходный текст хранится один раз. Динамические классы хранятся строками в справочнике и таблице связей. Никаких столбцов или таблиц на каждый класс.
- Сохранять версии результатов, происхождение данных, человеческие исправления и возможность отката.
- Не запускать массовое обучение, внешнюю рассылку или публикацию на сервере автоматически.
- Не создавать веб-страницы для ТЗ, планов и отчётов разработки.
- Работать только над текущим этапом. Следующий этап автоматически не начинать.
- Не перечитывать весь проект на каждом этапе; сначала читать `docs/IMPLEMENTATION_STATE.md`, `docs/CONTRACTS.md` и относящиеся к задаче файлы.
- Не заявлять об успешной проверке, если она не выполнена.
- Отсутствующие реальные токены не подменять фиктивными результатами; внешние интеграции проверять отдельно от автономных тестов. Тестовые заглушки допустимы только в явно автономных тестах.
- Существующие пользовательские изменения не очищать и не перезаписывать. Копировать обычные файлы, без символических и жёстких ссылок. Не переносить `.git`, окружения, кеши, `.env`, Telegram-сессии и секреты.
- Веб: администрирование и поиск. Telegram: поиск и подписки. OWNER управляет системой; USER ищет и управляет только своими подписками. Приоритет вакансий; резюме сохраняются для исследований.
- Только уже реализованные источники. Неизвестные поля остаются неизвестными. Сначала точная дедупликация; автоматическое выделение нескольких вакансий из поста отложено.
- Выполнять команды из корня нового проекта его `.venv/Scripts/python.exe`. Алгоритмы обработки текста менять только при доказанной необходимости.
